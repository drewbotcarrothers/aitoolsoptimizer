## What GitHub Copilot is

GitHub Copilot is the AI coding assistant built by GitHub. It started as autocomplete for code and has grown into a platform of agents: it suggests code as you type, answers questions in chat, reviews pull requests, and its **cloud agent** can take an issue, write the code and open a pull request for you to review.

Copilot works in VS Code, Visual Studio, Xcode, on GitHub.com and in other supported environments. Paid plans also give you access to third-party agents, including Claude Code and Codex, and let you choose among models.

## Key features

### Code completion and next edit
Inline suggestions and predicted next edits; unlimited on Business plans.

### Copilot Chat
Ask questions about code, errors or your repository.

### Cloud agent
Assign work and let Copilot implement it in the background, then review the pull request.

### Code review
AI review comments on pull requests.

### Models and third-party agents
Pick models per task; Pro+ adds premium models such as Opus.

### Governance
Access controls, budget controls, audit logs and IP indemnity for organizations.

## Best use cases

- **Daily coding:** speed up boilerplate, tests and refactors with completions.
- **Issue backlog:** assign small bugs to the cloud agent.
- **Code review:** get a first-pass review before human reviewers.
- **Onboarding:** ask chat to explain an unfamiliar codebase.

## How to get started

1. Sign in to GitHub and enable Copilot Free.
2. Install the Copilot extension in VS Code, Visual Studio or Xcode.
3. Start typing and accept suggestions with Tab.
4. Open Copilot Chat and ask about your project.
5. Upgrade to Pro to try the cloud agent and code review.

## Tips and tricks

- **Write descriptive comments and function names** to guide suggestions.
- **Give the agent well-scoped issues** with clear acceptance criteria.
- **Watch credit usage** when using premium models.
- **Always run tests** on AI-generated changes.

Example agent task:

> Add input validation to the signup form: email must be valid, password at least 12 characters with one number. Show inline error messages, add unit tests for each rule, and don't change the API.

What Is AI Latency vs Throughput? (2026): One Wait, or the Whole Queue

By Andrew · October 24, 2026

Latency is how long one person waits for an answer. Throughput is how much work the system finishes in that same stretch of time. A demo can feel instant and still fall behind when fifty people send prompts at once. You track both, because a change that shortens one wait can shrink the number of waits you can serve.

The bill for each answer is what AI inference is. The unit on that bill is what AI tokens are. A record of one slow request is what AI observability is.

A slow tool is a latency incident. A full queue is a throughput incident. Logging only an average for the week hides both. The trace that separates them is the same one observability asks you to keep: prompt, tools, tokens, and the two times.

Where a plan pretends to be a speed promise

A chat subscription sells a cap, not a latency SLA. ChatGPT Plus is $20 a month. Go is $8. Pro starts at $100. Hitting Plus in the middle of the day is a throughput limit on that seat. It does not tell you how many milliseconds the next token took before the cap. The ladder is ChatGPT Go vs Plus vs Pro.

Claude Pro is $20 a month, or $17 billed annually. Max from $100 is a usage multiple of Pro, recorded as 5× or 20×. Buy Max when Pro stops a workday. Do not buy it because one PDF felt slow. A long file and a short file pasted fifty times spend the cap differently. The split is Claude Pro vs Max.

DeepSeek chat is free. The API posts a token price, not a latency number. Flash input on a cache miss is $0.15 per million tokens off-peak and $0.30 at peak. What you can change without inventing a benchmark

Shorten the prompt that repeats. A stable prefix is the job of a context cache. A cache hit can cut the input bill. It does not, by itself, publish a faster time-to-first-token.

Ask for less output when the user is waiting. Throughput of a live chat is often limited by how many tokens you generate, not by how clever the question was. A one-line answer finishes sooner than a memo. That is a product choice.

Separate the live path from the pile. A person at a keyboard cares about latency. A folder of documents that can wait cares about throughput and price. Mixing them on one endpoint is how the interactive user inherits the batch’s queue. Speculative decoding, when a vendor uses it, is a latency technique. The definition is what speculative decoding is. Quantization is a memory technique that can change both clocks. The definition is what quantization is.

Time your prompt, on your plan. This directory does not keep a leaderboard of milliseconds. A number from someone else’s hardware will not match your tool calls.

FAQ

Is a higher token-per-second number the same as throughput?

It is one way to describe throughput for a single stream. Account throughput is how many of those streams finish before the plan, the queue, or the GPU runs out. Quote the unit. “Fast” is not a unit.

Does a bigger context window lower latency?

A larger window lets you send more. More input usually takes more work before the first token. The ceiling this site has recorded, and the practical limit, is what a context window is.

Should I optimize latency or throughput first?

Optimize the complaint you can reproduce. One slow ticket is latency. A job that misses a morning deadline is throughput. Fix the one your users actually hit.

Will a more expensive chat plan make tokens arrive faster?

It raises how much you may use. Treat a speed change as unproven until you time the same prompt on both plans. The receipt and the stopwatch answer different questions.

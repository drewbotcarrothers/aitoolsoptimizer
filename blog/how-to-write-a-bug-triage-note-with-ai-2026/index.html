How to Write a Bug Triage Note with AI (2026): Repro, Severity, Owner

By Andrew · October 24, 2026

A bug triage note written with AI is a short record: what broke, how you reproduced it, how bad you say it is, who owns the next step, and what you do not know yet. The model can tighten the sentences you paste. It cannot assign severity, name a root cause, or promise a ship date. If the repro is missing, the note says it was not reproduced. A tidy theory is not a ticket.

The public version, if customers can see the failure, is how to write a status page update with AI. The write-up after you know the cause is how to write a postmortem with AI. Reading one Python traceback, before this note exists, is ChatGPT vs Claude for Python debugging.

What the note is allowed to say

LineWho owns the factThe model may
SymptomWhat you observed: the error, the screen, the wrong numberDescribe it. It may not rename it as a deeper failure
ReproThe steps you actually ran, including the versionFormat the steps. It may not add a step you did not take
SeverityYou, from your scaleRepeat the level you wrote. It may not escalate it
ScopeWho is affected, if you measured itNot a percentage you did not paste
Owner and next stepThe person you named, and the actionNot a fix, and not a date you did not commit
UnknownsThe cause, until someone proves itLeave the cause as unknown
flowchart TD
  see["You see a failure"] --> repro{"Did you reproduce it?"}
  repro -->|No| note1["The note says not reproduced, plus what you tried"]
  repro -->|Yes| paste["Paste steps, version, expected, actual, and your severity"]
  paste --> draft["AI drafts the note. It does not pick an owner"]
  draft --> owner["A person assigns the owner and the next check"]
  note1 --> owner

A root cause the model guessed will be copied into the postmortem later if you are not careful. Keep the word “unknown” until a change in the code or the config explains the symptom. That discipline is the same one incident notes use. The hour of a customer-facing failure is what AI incident response is.

Where the note is drafted

The paragraph. Claude Pro is $20 a month, or $17 billed annually. Put the severity scale in a Project so the model stops inventing P0. The review is Claude review.

The chat next to the ticket. ChatGPT Plus is $20 a month. Business is $20 a user a month billed annually, minimum two, when the paste includes a customer name. Strip the name if the ticket does not need it. The ladder is ChatGPT Go vs Plus vs Pro.

The ticket itself. Notion AI Business is $20 a seat a month if the board lives in Notion. The note is a row with an owner field a person fills. Plus at $10 is not the full AI tier. The invoice is Notion AI pricing explained.

The repro in the editor. Cursor Plus is $8 a month, or $80 a year, when the next step is a failing test you will run. The note does not replace the test. The invoice is Cursor pricing explained.

A prompt that holds the line:

“Draft a bug triage note from these facts only. Include symptom, environment, repro steps I listed, expected versus actual, the severity I assigned, and unknowns. If I did not name an owner, write Owner missing. Do not propose a root cause. Do not invent log lines. Do not set a ship date.”

The person who sets severity is what human-in-the-loop AI is.

Severity is a decision, not a mood

Write the scale where the team can see it: what “high” means in your product, in one sentence each. The model may format examples you provide. It may not decide that a typo is high because the prose sounds urgent, or that a data loss is low because the ticket is short.

If you did not reproduce the bug, say what you tried and what you need from the reporter. Do not let the draft imply you saw it. Duplicate tickets should point at the original note, not grow a second theory.

Customer impact stays numeric only when you counted it. “Some users” is honest. “40 percent” is a measurement. The log that would support a count is what structured logging for AI is, when the bug is in a model path. A model bug and a button bug can share this note shape. They should not share a guessed cause.

FAQ

Is this a postmortem?

No. A triage note is the open ticket. A postmortem is what you write after the cause and the fix are known. Using this workflow for the later document will hide the unknowns you still have. Use the postmortem guide when you are done.

Can AI set priority from the traceback?

It can restate the traceback. Priority is impact and urgency on your scale. A scary stack trace in a script nobody runs is not automatically the top of the queue. You rank it.

What if there are no repro steps?

Then that is the note. “Not reproduced. Need the account type and the time.” Shipping a hypothetical fix for an unreproduced bug is how you change the wrong line. The debugging session comes after you can see the failure.

Should the note include a patch?

Only a patch a person has run. A suggested diff in the ticket, labeled as untested, is optional and easy to mistake for a fix. Prefer a link to the test you ran. The model does not merge.

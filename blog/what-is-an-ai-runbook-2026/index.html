What Is an AI Runbook? (2026): The Page the On-Call Opens

By Andrew · October 24, 2026

An AI runbook is the page an on-call opens for one model-backed feature: who owns it, how to tell it is unhealthy, which flag or key turns it off, what to tell customers, and which prompt version is live. A chat transcript is not a runbook. A runbook has an owner and a date, and it is updated when the feature changes.

The path that uses that page during a bad day is what AI incident response is. The place a fact is allowed to live is what a system of record for AI is. The checks the page should point at are what AI observability is and what AI SLA monitoring is.

A runbook that will fail you

It fails if the flag name is stale, if the only copy is in a chat, or if the customer note includes a cause you have not confirmed. It also fails if it includes steps for attacking the system. Keep those out. If the feature reads untrusted text, point at the control you already run, described at a policy level in what a prompt injection defense is.

Spend limits belong on the same page when money is part of “unhealthy.” That ceiling is what an AI budget cap is.

FAQ

How long should a runbook be?

One page for one feature. If the off switch takes more than a few numbered steps, the feature is harder to operate than the document can fix. Shorten the path, then the page.

Can one runbook cover every model?

No. Each feature has its own flag, owner, and customer impact. A single “AI runbook” becomes a list of links. The links are fine. The steps have to be specific.

How often should someone test it?

When the flag, the prompt version, or the owner changes, and on a schedule you can keep. A date in the future with no name is not a test. The eval habit for the model itself, separate from the on-call page, is what AI eval testing is.

Should the runbook live in the repo?

The off-switch steps can live next to the flag in the repo if that is where engineers look. The customer sentences can live in the wiki. Write down which copy wins when they disagree.
